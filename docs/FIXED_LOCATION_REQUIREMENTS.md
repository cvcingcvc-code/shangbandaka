# 固定地点模拟与可靠停止：冻结需求

冻结日期：2026-11-04。此文件是实现和验收基准；只有取得对应证据，才可将结果记为 PASS。

## 1. 唯一流程和范围

中文搜索 → 用户明确选择搜索结果 → 地图确认 → 开始 → 持续提供该地点 → 停止。保留运行状态、地图手动选点和经纬度备用输入。运行期间目标经纬度不可自动更换；重复点击不得建立重复模拟任务。

除必要修复和诊断外，不增加账号、轨迹、自动签到或其他功能。地图当前位置、微信发送位置界面及指定的授权小程序都是必测目标，不能缩减为本应用自己的回调成功。当前没有指定小程序名称和可复现测试页面，应在验收记录中补齐后执行。

## 2. 先查位置来源，再决定接口

在 REDMI K80 Ultra 真机上，用独立读取应用分别实时订阅 GPS、network 和 Android 系统 fused。若设备具备可用 Google Play 服务，再单独测试 Google FLP；设备未具备时记录“不适用”及证据，不能把它当作 PASS。

每次回调记录设备时间、采集时间、坐标、坐标系、来源、精度、数据年龄及模拟标记。旧缓存与新回调必须区分。Android 系统 fused 和 Google FLP 为不同接口。融合定位是否需要新增模拟入口，取决于真机可行性结果；旧缓存不同不足以判断根因，不据此盲目增加模拟接口。

## 3. 服务生命周期

明确区分：准备、验证中、运行、停止中、清理失败、已解除且等待正常定位、已停止且正常定位取得。启动或注入失败另有具体原因。

开始、停止请求按顺序处理；重复请求不产生重复任务。部分注册失败时撤销本轮已完成操作，并保留未确认清理的记录。进程死亡、授权撤销与再次启动时，根据可确认的系统请求结果恢复；持久标记是待处理线索，不是服务存活或清理完成证据。不能仅清除标记宣称成功，也不能只依赖 `onDestroy()` 清理。

## 4. 坐标固定，时间持续更新

每次注入使用用户确认的同一目标经纬度，更新有效且合理递增的时间戳。初次验证排除本次启动前数据；运行期间持续验证必要定位入口的新回调。注入异常、授权丢失或验证超时后立即撤销“运行正常”，显示失败阶段和具体原因，并尝试清理。

如将来经可行性验证采用 Google FLP，应检查进入 mock mode、注入和退出 mock mode 的异步结果；未完成的 Task 不能当作成功。[Google 官方接口](https://developers.google.com/android/reference/com/google/android/gms/location/FusedLocationProviderClient)

## 5. 停止分为两步

第一步停止注入，解除测试 provider 或适用模拟模式，确认相关调用结果；第二步由独立读取端取得停止之后的新鲜非模拟位置。第一步成功但第二步尚未取得时，界面显示“模拟已解除，等待正常定位”，不能显示已恢复完成。

第三方仍显示旧缓存时单独记录其时间和现象。已经发出去的位置消息不会随停止而改变；验收应重新打开发送位置界面，检查新的当前位置。

## 6. 真机验收

至少十轮开始—停止，覆盖持续运行、切换应用和锁屏。逐轮记录独立标准接口、地图当前位置、微信发送位置界面、指定授权小程序和停止恢复。

比较同一个实际地点，注明 WGS-84 / GCJ-02 / BD-09 等坐标系；不能直接把不同坐标系的数值差异视为模拟失败。地图镜头、选点标记和历史位置消息都不能证明当前定位成功。发现不一致时先保存日志、截图与时间对应关系，再修改代码。执行表见 [真机验收记录](PHYSICAL_DEVICE_ACCEPTANCE.md)。

## 7. 结果和发布

- PASS：该项已经实际测试且证据满足要求。
- FAIL：该项已经实际测试，出现目标地点错误、无法停止或其他不满足需求的行为。
- BLOCKED：手机未连接、权限或测试条件缺失、证据不足或未执行。

如某目标应用在既定边界内无法接受模拟坐标，明确记为未满足需求。项目不隐藏 `isMock`，不绕过第三方模拟位置检测、考勤风控或身份校验，也不承诺全应用覆盖；IP 归属地不属于 GPS 模拟效果。

完成必要回归后，用原 Release 签名、新版本号和新 SHA-256 发布候选包，保留旧版本。密钥不入库；签名不可用时不得擅自换证书。真实手机测试未通过前，不宣布整体修复完成或晋级稳定版。
