# rc.12 联网与定位复验

2026-11-06。复验对象为此前签名并保留在本地的 `1.1.2-rc.12` / code 15，源码提交 `22639c0a0773a9a48122cd48bfeb9710677def6b`，APK SHA-256 `DA2FBA08A6DFA762477ACF74F0667FB5500E641A7A9B11E6E6864FCD61DF1576`。环境为 API 35 Android 模拟器，720 × 1280 / 320 dpi。测试代理只设在本轮只读模拟器，使用真实 HTTPS 和现有本机网络代理。

| 项目 | 实测结果 |
| --- | --- |
| Windows 连通性 | PASS。Nominatim 和 OpenStreetMap 瓦片经现有本机代理返回 HTTP 200。 |
| 系统 Geocoder | BLOCKED。实际在首页输入 `Tokyo Tower`，系统搜索超时。 |
| Nominatim | PASS（东京塔）。点击联网备用搜索得到「東京鐵塔，港區，日本」一条结果。点结果、等地图就绪、按确认，首页写入 WGS-84 `35.6584491, 139.745536`。 |
| 地图手动选点 | PASS。显示真实 OSM 瓦片，实际点图后出现标记，按确认返回首页显示「已确认：地图点选」。 |
| 固定模拟与独立读取 | PASS（模拟器）。从首页启动，独立 Reader 收到 GPS、network、系统 fused 的新回调，均显示同一东京塔位置和 `isMock=true`。未测试 Google FLP。 |
| 切换与熄屏 | PASS（模拟器）。切到 Reader 后熄屏，`dumpsys power` 为 `Asleep`。约 18 秒后 GPS、network 均有新时间戳的同一模拟坐标，返回界面仍显示运行。 |
| 停止和恢复 | PASS（模拟器 GPS 与系统 fused）。从界面点停止，显示「模拟已解除，等待正常定位」。随后给模拟器 GNSS 提供测试基线，Reader 收到 `37.421998, -122.084000`、`isMock=false` 的新回调。未取得正常 network 新回调。 |
| 上海地点数据覆盖 | 分项结果。Windows 实际查「上海中心大厦」返回 1 条精确结果，WGS-84 `31.2356497, 121.5012544`，地址包含银城中路 501 号。直查「上海市浦东新区世纪大道100号」得到 HTTP 200 和空结果，该地址在本次备用服务查询中 FAIL。 |
| 百度官方 Android 客户端 | PASS（安装与外部跳转）。在模拟器安装百度签名的 `com.baidu.BaiduMap` 22.1.20，点本应用的「百度地图查地址」，日志记录 `ACTION_VIEW baidumap://map/…` 进入百度客户端。客户端要求先同意其服务协议与隐私政策，选择不同意后显示退出或同意。真实百度搜索结果和蓝点为 BLOCKED。 |

此次审计还发现，rc.12 首页将 `100-1号` 和 `1001号` 归一成同一文字，改输入时可能保留旧确认坐标。rc.13 用保留标点的输入判断变化，并在编号地址匹配时保留数字之间的连字符，拒绝不同门牌。该修复不增加搜索源或模拟入口。

截图、模拟器 UI 状态和独立定位记录存于本地 `build/acceptance-rc12-online`。真机、微信发送位置及授权小程序仍无验收证据，状态为 `BLOCKED: PHYSICAL_DEVICE_NOT_TESTED`。
