# 2026-11-04 真机搜索与定位故障现场

本轮设备已授权连接：REDMI K80 Ultra（25060RK16C），Android 16 / API 36。开始检查时安装主包 rc.9 / versionCode 12。此记录是故障调查，不代表完整验收通过。

## 已确认事实

- 安装与启动：已安装 rc.9，主界面可启动，精确和大致位置权限已授予，系统定位开关为 true。仅对应安装/启动，不代表模拟成功。
- 最初模拟应用 AppOp 为默认 deny，没有正在运行的 MockLocationService。用户重新在开发者选项选择应用后，实际复查为 allow。不能把精确定位权限与模拟位置授权混为一项。
- 主界面保留查询“上海现代化工”，但旧选点是台湾的同名餐馆，运行状态为尚未开始。未对该错误旧选点启动模拟。
- 独立复现相同 Nominatim 请求，HTTP 200，返回台湾餐馆、深圳银行和昆山地铁站等 3 个无关结果；这是结果匹配失败，不是 HTTP 成功即可视为搜索成功。响应原文保存在本地工作目录，未硬编码学校坐标。
- 手机拒绝电脑注入输入事件（INJECT_EVENTS），也拒绝 USB 安装独立读取工具（INSTALL_FAILED_USER_RESTRICTED）。未绕过这些限制。
- 新的只读诊断工具 v4 / 1.3-diagnostics 已编译及 lint 通过，放入手机 Download，等待用户手动安装。它增加系统 Geocoder 后端探针，不修改模拟状态；只保存显式测试地名的响应，不保存 Reader 取得的实时位置。
- 系统网络及融合 provider 分别绑定 Xiaomi 服务；Google Play services 包存在并启用，但 Google FLP API 是否可正常调用尚未验证。不能从安装包存在推断 FLP 可用，也未新增任何融合定位模拟。

## 正在实施的修复与验证顺序

1. 搜索优先尝试系统中文 Geocoder，区分无实现、空结果、错误和超时；保留用户触发的联网备用搜索。不能把城市中心当学校成功结果。
2. 检查明确城市及具体中文关键词；“上海…”不收录台湾、深圳或昆山的宽泛同名结果。所有候选显示来源、原始名称和地址，由用户地图确认，不自动选第一条、不自动改地点名称。
3. 首页直接显示模拟授权缺失，未配置时不能开始。运行期间只保持已确认目标。
4. 在工具安装后，先取得三路未模拟的新回调基线，再进行受控开始、持续运行和停止。位置样本必须晚于本轮操作，且在明确的新鲜窗口内；旧缓存和地图镜头不是成功证据。
5. 两个目标地名的完整文字仍待用户输入。不能将语音推测的名字写入代码或冒充实际检索结果。

完整目标与十轮验收规则保持 [冻结需求](FIXED_LOCATION_REQUIREMENTS.md) 和 [验收表](PHYSICAL_DEVICE_ACCEPTANCE.md)。原始真机 logcat、UI 与 dumpsys location 已仅保存在本地工作目录；含实际位置的原始文件不上传到公开仓库。
